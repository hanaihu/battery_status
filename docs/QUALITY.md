# 质量要求

本文件定义本项目的质量目标与取舍。**质量属性是预算分配，不是功能清单**——每条要求的成本由
单人维护、常驻后台、无运行时依赖、依赖未文档化系统行为这四个约束决定。

新增功能前先看这一页；与本文冲突的实现视为缺陷。

---

## 一、约束

| 约束 | 推论 |
|---|---|
| 单人维护 | 不做需要持续投入才能维持的质量 |
| 常驻后台、用户不会主动看 | 可靠性 = 不崩不吵；可观测性 ≠ 监控面板 |
| 依赖未文档化系统行为 | 隔离比抽象重要，脏代码集中在一处 |
| 单 exe、无运行时 | 体积与依赖是硬约束 |

---

## 二、优先级

| 属性 | 级别 | 落点 |
|---|---|---|
| 可靠性（降级不崩） | **P0** | 三态模型 + provider 隔离 + IO 超时 |
| 资源不泄漏 | **P0** | RAII 句柄、字体/图标复用、环形日志 |
| 安全（不可信输入） | **P0** | 长度校验、bidi 过滤、不提权、不联网 |
| 可扩展（长尾设备） | P1 | provider 表，边界到 VID/PID 分发为止 |
| 可观测 | P1 | `--dump` + 环形日志 + 零网络 |
| 可配置 | P2 | 少量开关、容错解析、原子写 |
| 开闭性 / 模块化 | P2 | 只冻结两个接缝 |
| 可测试 | P2 | 协议解析写成纯函数 |
| 性能 | P2 | 空闲 0% CPU、< 5 MB |
| 跨平台 | — | 仅 Windows，不做 |

---

## 三、P0：可靠性

### 3.1 三态模型

每个设备的电量必须是以下三种之一，UI 三种表现必须不同：

| 状态 | 含义 | 显示 |
|---|---|---|
| `Fresh` | 本次轮询读到的值 | 正常显示 |
| `Stale` | 读失败，保留上次已知值 | 变灰，附时间戳 |
| `Unknown` | 从未读到 | 显示占位符，不是 0% |

**禁止**用 `0%` 或"不显示"来糊弄未知状态。

### 3.2 provider 隔离

每个 provider 独立执行、独立失败。一个 provider 抛错或超时，只允许少一行数字，不允许影响
其余 provider，更不允许影响 UI。

### 3.3 IO 不得阻塞 UI

`HidD_GetFeature` / `SetupDiGetClassDevsW` 等调用可能阻塞数百毫秒甚至更久。

- 轮询在独立线程，UI 线程永不等待 IO
- 每轮轮询有整体预算，超时即放弃本轮并标记 `Stale`
- 主线程只消费已经算好的快照

## 四、P0：资源不泄漏

常驻程序最常见的死法是"跑了几个小时后自己消失"。以下为硬性要求：

| 泄漏源 | 要求 |
|---|---|
| 文件 / HID 句柄 | 每个 `CreateFileW` 必须配 RAII，`HidD_GetPreparsedData` 同理 |
| GDI 对象 | 默认上限 10000；字体/画笔在初始化时建、销毁时删，`Paint()` 内**禁止**创建 |
| 用户对象 | 窗口、图标、菜单在 `Destroy` 路径上逐一释放 |
| 日志 | 环形，体积上限 256 KB × 3，超出覆盖最旧 |

判断标准：**每个 `Create*` 都必须能指出它在哪被销毁。**

## 五、P0：安全

### 5.1 权限

**不申请管理员权限。** 这是本项目最重要的安全属性，也是与"注入类"工具的根本区别。

### 5.2 设备数据是不可信输入

设备返回的任意字节都按不可信处理：

- 解析前先校验实际长度，不信报文里的长度字段
- 所有下标、偏移、计数字段做边界检查
- 不用 `strcpy` / `sprintf` / `wcscat` 处理设备名

### 5.3 设备名的特殊风险

- 必须过滤控制字符与 bidi 覆盖字符（U+202A–U+202E、U+2066–U+2069），否则可在 UI 上
  伪造文字顺序，形成视觉欺骗
- 设备名只能作为 UI 文本与日志**内容**，**禁止**参与路径或注册表键名拼接

### 5.4 网络

- **零网络访问**：不联网、不上报、不检查更新
- 不做自动更新（自签名小工具最大的攻击面）
- 该承诺写入 README，属于产品契约

## 六、P1：可扩展

### 6.1 provider 表

```
static const Provider kProviders[] = {
    { "logitech", PollLogitech },
    { "bt",       PollBluetooth },
    { "hid",      PollGenericHid },   // 兜底，必须最后
};
```

新增厂商 = 新增一个 `.cpp` + 表里加一行。核心代码不动。

### 6.2 抽象边界

只冻结两个接缝：

1. `DeviceStatus` 数据模型
2. `Provider` 函数签名

其余允许耦合。**明确不做**：

- 把 UI 抽象成插件系统
- 设计"协议描述 DSL / 配置化协议"
- 预留运行时加载 DLL 的插件接口

理由：在只有 1 个真实协议时做的抽象，会在见到第 3 个协议时被推翻。

## 七、P1：可观测

| 形式 | 要求 |
|---|---|
| `--dump` | 打印所有候选设备、命中的 provider、读到的值、失败原因 |
| 日志 | `%LOCALAPPDATA%\BatteryStatus\`，环形，默认仅 WARN/ERROR |
| 状态视图 | 托盘菜单内可查看上次刷新时间与各设备数据来源 |
| 网络 | 无 |

明确不做：性能计数器、结构化日志格式、采样、远程日志。

---

## 八、P2：可配置

配置项是负债。只暴露用户真正会改的项，实现细节（超时、重试次数）不得暴露。

- 解析失败必须回退默认值并记一条日志，**不得崩溃**
- 写入使用临时文件 + `MoveFileExW(..., MOVEFILE_REPLACE_EXISTING)` 原子替换
- 配置来源优先级：内置默认 < 用户文件 < 命令行

---

## 九、P2：可测试

硬件无法进 CI，因此：

- 协议解析写成纯函数：`const BYTE* + len → 结构体`，**不得**在内部发起 IO
- 测试通过构造字节流覆盖：正常值、越界、过短报文、异常标志位
- 真实设备的 `--dump` 输出保存为 fixture，用于回归

---

## 十、P2：性能

| 指标 | 目标 |
|---|---|
| 空闲 CPU | ≈ 0%（每秒一次布局校正，工作量必须极小） |
| 常驻内存 | < 5 MB |
| 二进制体积 | < 500 KB（`/O2` + 静态 CRT + 无重依赖） |
| 轮询间隔 | 默认 60 s；与"外设自身耗电"绑定，低频优先 |

---

## 十一、已确定的实现决策

| 决策 | 取值 |
|---|---|
| 错误模型 | 返回码 + 状态枚举，全程不抛异常（`/EHsc-`） |
| 电量状态 | `enum class Level { Unknown, Stale, Fresh }` |
| 诊断来源 | `DeviceStatus::source` 字符串（如 `"logitech"` / `"bt"` / `"hid"`） |
